# 个人进度工作台 · 产品规划文档（PRD v0.1）

> 一句话定义：**一个只有一屏的个人作战台 —— 30 秒建好一个项目，每天点一下打卡，它替你盯着截止日和停滞信号，并在每天结束时给你一份可复制的进度总结。**

---

## 1. 为什么要做（Why）

| 现状痛点 | 具体表现 | 本产品的解法 |
|---|---|---|
| 事情散在多处 | 求职、投资跟踪、家庭旅行、AI 平台…… 想法记在备忘录/微信收藏/脑子里，没有统一入口 | 统一「项目」容器，一条记录 = 一件事 + 优先级 + 截止日 |
| 进度靠回忆 | 一周没碰的项目悄悄烂尾，直到截止日才发现 | 进度由任务完成率**自动算**，不靠手动填百分比 |
| 没有外部压力 | 没人催，就容易拖 | **到期前主动提醒**（3 天 / 1 天 / 逾期）+ **停滞检测**（N 天无打卡） |
| 缺乏正反馈 | 忙了一天说不清做了什么 | 每日复盘：今天推进了哪些项目、完成任务数、明日到期清单，一键复制成日报 |
| 工具太重 | Notion/Trello 配置成本高，打开就劝退 | 单文件网页，双击打开即用，零配置、零登录、零网络依赖 |

**产品目标（可衡量）**
1. 新建一条项目 → 从打开页面到完成录入 ≤ 30 秒
2. 每天打开工作台 3 次以上（早看预警 / 中打卡 / 晚看复盘）
3. 逾期项目数长期 ≤ 进行中项目总数的 10%

**非目标（Non-goals）** — 明确不做，防止范围蔓延
- ❌ 不做多人协作、不做权限、不做评论 @ 人
- ❌ 不做甘特图、不做工时统计、不做日报自动上报
- ❌ 不做手机 App、不做云端同步（V1）
- ❌ 不做 AI 自动判断进度（进度来源 = 你的手动打卡，AI 只做**汇总与提醒**，不做臆测）

## 2. 概念模型（数据模型）

```
Project（项目）
├── 基础：名称 / 描述 / 优先级 P0·P1·P2 / 截止日 / 状态（进行中·已完成·已归档）
├── 关键任务：Task[]
│     └── 子任务：SubTask[]（可选）      ← 叶子节点 = 进度的真相来源
└── 打卡：CheckIn[] —— 时间 / 当时进度 / 已完成叶子数 / 备注   ← 形成时间线

最多 3 层：项目 → 关键任务 → 子任务，不再往下递归。
DaySummary（每日总结，由 CheckIn 实时派生，不单独存储）
```

**核心原则：进度 = 叶子节点完成率，不是手填的数字。**
叶子定义：**有子任务的任务 → 它的子任务是叶子；没有子任务的任务 → 它自己是叶子。**

```
项目进度   = 已完成叶子数 / 叶子总数 × 100
父任务进度 = 其下子任务完成率（子任务全完成 → 父任务自动标记完成）
```
> 为什么按叶子而不是按"关键任务个数"算：否则「写一份报告」和「打个电话」权重相同，进度会失真。
> 只有整个项目没有任务时，才回退到手动填百分比。

| 字段 | 类型 | 说明 |
|---|---|---|
| `Project.priority` | `P0 / P1 / P2` | P0 必做·红线，P1 重要，P2 有空做 |
| `Project.due` | `YYYY-MM-DD \| 空` | 空 = 无截止日，不参与提醒 |
| `Project.status` | `active / done / archived` | |
| `Task.children` | `SubTask[] \| 空` | 空则 Task 自身即为叶子 |
| `CheckIn.progress` | `0-100` | 打卡瞬间的进度快照，用于画趋势 |
| `CheckIn.note` | `string` | 「今天做了什么」，复盘文本的素材 |
| `Task.pri` | `P0/P1/P2 \| 空` | 空 = 跟随项目优先级，不单独显示标签，避免表格吵 |
| `Task.due` | `YYYY-MM-DD \| 空` | 任务自己的完成日期，参与提醒 |
| `Task.repeat` | `none/daily/weekly/monthly/every_n` | 循环规则，**只对末级任务生效** |
| `Task.everyN` | `number` | `repeat=every_n` 时的间隔天数 |
| `Task.lastDone` | `YYYY-MM-DD` | 最近一次完成日，用于计算项目"是否停滞" |

### 循环任务（Repeat）—— 一条重要规则

**循环任务不计入项目进度。**

循环任务是「永续维护型」（每天复盘、每周整理），不是「有终点的交付物」。如果计入，今天勾完进度涨、明天重置进度跌，进度条会永远震荡，整个进度表失去意义。

| 行为 | 规则 |
|---|---|
| 勾选后 | 记录 `lastDone=今天`，到期日自动推进到下一周期，状态重置为**未完成** |
| 周期推进 | `每天 +1d` / `每周 +7d` / `每月 +1月` / `每N天 +N`；若已过期则连续推进到下一个未过期周期 |
| 进度计算 | 分子分母都排除循环任务；父任务是循环则整条子树排除 |
| 生效范围 | 只对末级任务生效（有子任务的任务，完成态由子任务决定，设循环无意义） |
| 展示 | 名称后带 `⟳ 每天` 蓝色标签；进度表"完成"列显示 `—` |
| 停滞判断 | 完成循环任务也算"动过"，项目不再显示停滞 |

## 4. 信息架构

```
进度台（单页三 Tab）
├── ① 概览（今天该看什么）— 只有两块，不放冗余统计
│   ├── ⚠️ 需要关注（项目级 + 任务级）
│   │     · 项目：逾期 / 今天到期 / 3 天内 / 停滞≥3 天
│   │     · 任务：逾期 / 今天到期（含循环任务"今天该做"），带「完成」一键勾
│   │     · 去重：项目已逾期/今日到期时，不再重复提醒它下面的任务
│   └── 进行中的项目：卡片流，按紧急度排序
├── ② 进度表（全局一眼看完，树形三层，9 列）
│   ├── 筛选：搜索（含任务名）/ 状态 / 优先级 / 排序 + 全部展开折叠
│   ├── L1 项目行：优先级 · 截止 · 剩余 · 总进度 · 完成数 · 状态 · 最近更新 · 打卡
│   ├── L2 关键任务行：勾选框 · 优先级 · 自己的截止日 · 子任务进度 · 设置 / 删除
│   └── L3 子任务行：勾选框 · 优先级 · 截止日 · ⟳ 循环标签 · 设置 / 删除
└── ③ 复盘（每天收尾）
    ├── 今日总结卡（打卡次数 / 完成任务 / 覆盖项目）
    ├── 近 7 天打卡条形图
    ├── 各项目进度增量榜
    └── 一键生成总结文本 → 复制
```

## 5. 关键交互流程

| 流程 | 路径 | 关键细节 |
|---|---|---|
| 建项目 | 头部「+ 新建项目」→ 填表 → 保存 | 任务行可挂子任务（＋子任务），`Ctrl+Enter` 保存 |
| 推进进度 | 进度表直接勾选任务/子任务，无需进详情页 | 最短路路径：勾选即保存并重算 |
| 父任务操作 | 点关键任务的勾选框 | 一键全选/全清其子任务（当前全完成 → 再点则全清） |
| 打卡 | 点卡片 → 右侧抽屉 → 勾任务 / 写备注 → 「打卡」 | 打卡后进度条动画更新，时间线新增一条 |
| 处理逾期 | 首屏提醒条 → 「去打卡」/「顺延 7 天」/「标记完成」 | 一步解决，不用来回跳页 |
| 每日收尾 | ③ 复盘 Tab → 看总结 → 「复制总结」 | 输出可直接粘贴到日记/微信的纯文本 |
| 防丢 | 头部「数据」→ 导出 JSON | 建议每周导出一次 |

## 6. 计算规则（写死在逻辑里，避免歧义）

**进度计算**
```
叶子集合 leaves(t) = t.children.length ? t.children : [t]   // 父任务有子节点则不算叶子

若有任意叶子节点：
    项目进度 = 已完成叶子数 / 叶子总数 × 100
    关键任务进度 = 其叶子的完成率；子任务全完成 → 父任务自动 done
若整个项目没有任何任务：
    项目进度 = 最近一次 CheckIn.progress，无则 0
status = done 时 → 进度强制 100
```

**项目截止日（派生）**
```
项目截止 = 项目自设 due
           若无 → 取所有「非循环」任务/子任务中最早的 due（循环任务 due 会滚动，不能代表项目终点）
表格里派生出来的截止日标注「· 任务派生」，避免和自设的混淆
```

**循环任务推进**
```
勾选 → lastDone = 今天
     → 若 repeat != none：due = 下一周期，done 重置为 false
下一周期 = 每天+1d / 每周+7d / 每月+1月 / 每N天+N；若已过期则连续推进到下一个未过期周期
```

**停滞判断**
```
最近一次"动过" = max(最后一次打卡时间, 任意任务/子任务的 lastDone)
停滞天数 = 今天 - 最近一次动过   （完成循环任务也算动过）
```
```
① 逾期天数多的在前
② 剩余天数少的在前
③ 优先级 P0 > P1 > P2
④ 最近打卡时间早的在前
```

**提醒分级**

| 级别 | 触发条件 | 视觉 |
|---|---|---|
| 🔴 逾期 | `due < 今天` 且未完成 | 红色左边框 + 红底标签 |
| 🟠 今天到期 | `due == 今天` | 橙色 |
| 🟡 临期 | `今天 < due ≤ 今天+3` | 黄色，显示「还剩 N 天」 |
| ⚪ 停滞 | `active` 且 `≥3 天没动过` | 灰色，显示「已 N 天未更新」 |

**任务级提醒**（与项目级合并显示，按上面的级别混排）

| 级别 | 触发条件 |
|---|---|
| 🔴 任务逾期 | 任务/子任务 `due < 今天` 且未完成 |
| 🟠 任务今天到期 | `due == 今天`；循环任务文案为「今天该做 · 每天」 |

> 任务**不参与"3 天内"提醒** —— 任务数量远多于项目，全量提醒会把项目级信号淹没。
> 项目已处于逾期/今日到期时，跳过其下任务的提醒，避免同一项目刷两条。

**打卡热力**：近 7 天每天打卡次数 → 条形图，断档日一眼可见。

## 8. 用户故事（MVP 验收清单）

1. 作为**使用者**，我希望 30 秒内建好一个带截止日和任务的项目，以便不打断当前思路
2. 作为**使用者**，我希望在进度表里直接勾选关键任务 / 子任务，项目进度自动重算，以便既不用手动估算百分比，也不用逐个进详情页
3. 作为**使用者**，我希望打开页面就看到哪些项目逾期/临期，以便优先处理最紧急的事
4. 作为**使用者**，我希望点一下就能记录今天的进展，以便形成可追溯的时间线
5. 作为**使用者**，我希望每天有一份总结告诉我今天推进了什么，以便获得正反馈并规划明天
6. 作为**使用者**，我希望一键顺延逾期项目，以便快速清理提醒区而不必逐个编辑
7. 作为**使用者**，我希望数据能导出备份，以便换电脑/清缓存时不丢失
8. 作为**使用者**，我希望删除写错或已作废的任务，以便清单保持干净（而不是只能标完成）
9. 作为**使用者**，我希望给单个任务设优先级和完成日期，以便在项目内自己排先后，不必所有任务都跟着项目截止日走
10. 作为**使用者**，我希望把「每天复盘」「每周整理」设成循环，以便勾完自动出现下一次，不用每次手动重建
11. 作为**使用者**，我希望循环任务不影响项目进度百分比，以便进度条反映"交付物完成度"而不是"今天有没有打卡"

## 9. 产品健康度指标（个人工具也要有指标）

| 指标 | 定义 | 目标 |
|---|---|---|
| 日活打开率 | 每月有打卡的天数 / 当月天数 | ≥ 60% |
| 打卡覆盖率 | 当日有打卡的进行中项目 / 进行中项目总数 | ≥ 30% |
| 逾期率 | 逾期项目 / 进行中项目 | ≤ 10% |
| 烂尾率 | 停滞 ≥7 天的项目 / 进行中项目 | ≤ 15% |
| 建项目耗时 | 打开弹窗到保存的中位时长 | ≤ 30 秒 |

## 10. 风险与边界

| 风险 | 影响 | 应对 |
|---|---|---|
| 浏览器清缓存 → 数据全丢 | 高 | 内置导出/导入；首屏提示「本周还没备份」 |
| 打卡变成负担 → 放弃使用 | 高 | 打卡极简化：勾任务 + 一句话，≤10 秒完成 |
| 项目建太多 → 提醒区噪音 | 中 | 只提醒逾期/临期/停滞三类，且停滞阈值可调 |
| 无云端 → 换设备不可用 | 中 | V3 再评估；当前用 JSON 导出 + git 备份兜底 |
| 循环任务太多 → 提醒区被"今天该做"刷屏 | 中 | 任务级只提醒逾期/今天两级；项目已逾期时跳过其任务；必要时加"今日忽略" |
